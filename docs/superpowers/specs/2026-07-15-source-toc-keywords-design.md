# 原文页目录与正文关键词设计

**日期：** 2026-07-15
**状态：** 已确认，等待实现计划评审

## 目标

完善所有 `/sources/<slug>/` 原文详情页的右侧栏：在“原文信息”下增加可点击的“本篇目录”，并让“本篇涉及的关键词”根据原文正文实际出现的已登记文章关键词生成。股东会与股东信、演讲与访谈、李录演讲和访谈三类原文使用同一规则。

## 根因

当前页面用同一个 `citedBy` 数组同时表示“解读引用”和“本篇涉及的关键词”。`citedBy` 来自解读文章 frontmatter 的 `sources` 与原文标题之间的匹配，只能表示真实引用关系。现有解读文章没有把李录原文标题登记为来源，因此李录的 14 篇原文全部显示“本篇涉及的关键词（0）”，即使正文已经出现“能力圈”“复利”“护城河”等文章关键词。

## 数据语义

- `citedBy` 保持现状，只表示 frontmatter `sources` 建立的真实引用关系，并继续驱动“X 篇解读引用”。
- 新增纯函数，根据 `source.body` 是否包含 `article.keyword.trim()` 计算正文涉及的文章。
- 空关键词不参与匹配；相同关键词只显示一次。
- 为保证重复关键词的链接稳定，先使用现有文章展示排序规则排序，再保留每个关键词的第一个文章目标。
- 正文关键词关系不会写回文章 frontmatter，也不会增加“解读引用”数量。

## 页面结构

右侧栏顺序固定为：

1. 原文信息；
2. 本篇目录；
3. 本篇涉及的关键词；
4. 同类原文。

“本篇目录（N）”直接使用 `source.headings`，收录 Markdown 中全部 `##` 与 `###` 标题。每一项使用现有标题 slug 作为页内锚点；没有二、三级标题的原文仍显示“本篇目录（0）”。目录和关键词都复用现有 `info-panel`、`link-list`、`keyword-list` 样式，不新增 CSS 或客户端脚本。

“本篇涉及的关键词（N）”改用正文匹配结果，链接到对应 `/articles/<slug>/` 页面。没有匹配项时保留计数为 0 的空模块。

## 实现边界

- 在 `src/lib/relations.ts` 增加正文关键词关系函数，不改变现有引用映射函数。
- 在 `src/pages/sources/[slug].astro` 分别读取引用关系、正文关键词关系和标题目录。
- 不改动原文 Markdown、解读文章 frontmatter、自动正文交叉链接、原文分类、侧栏配色或移动端抽屉行为。
- 不为李录模块增加特例；三类原文共享相同行为。

## 验证

- 关系单元测试：正文出现的关键词被返回，未出现的关键词不返回，重复关键词去重。
- 语义隔离测试：正文关键词匹配不会改变 `buildSourceArticleMap()` 的真实引用结果。
- 页面模板测试：目录位于“原文信息”和“本篇涉及的关键词”之间，目录数量和锚点来自 `source.headings`，关键词数量和链接来自新的正文匹配结果。
- 运行 `npm run check`，确认内容校验、Astro 类型检查、Vitest 和静态构建全部通过。
- 检查一个李录构建页面，确认目录可跳转、关键词不再为空，并且“解读引用”仍保持真实数量。
