# 李录演讲和访谈原文模块设计

## 目标

在现有左侧导航的“原文”区块中新增第三个折叠组“李录演讲和访谈”，将 `/Users/ruimin/Desktop/code/invest_paper/投资大师汇总/李录/` 中现有的 14 篇 Markdown 全部纳入站点，并为每篇资料生成可独立访问的原文页。

站点构建与部署必须完全自包含，不依赖仓库外的绝对路径。原始正文保持不变；允许为适配站点而规范仓库内文件名和本地图片链接。

## 范围

### 纳入

- 复制李录目录中的全部 14 篇 Markdown，包括演讲、访谈、交流实录、讲座笔记和纪念文章。
- 复制 3 篇带图文章引用的 8 张 PNG 图片。
- 左侧“原文”新增“李录演讲和访谈”分组。
- 原文索引页与首页原文入口新增对应分组。
- 单篇原文页、站点地图、`llms.txt` / `llms-full.txt` 自动包含李录资料。
- 李录原文页沿用现有阅读页、目录、关键词自动链接与结构化数据能力。

### 不纳入

- 不改写、摘要或事实核查李录正文。
- 不把李录资料加入芒格解释文章的引用来源清单或文章生产语料清单。
- 不改变站点名称、现有芒格文章分类或“不可为清单”数据来源。
- 不从仓库外目录进行运行时或构建时读取。

## 内容落盘

在仓库根目录新增 `li-lu/`，与 `shareholders/`、`speech/` 平级。

- 14 篇 Markdown 扁平放入 `li-lu/`。
- 文件名去掉源目录中无意义的首尾空格，保留文章名称和年份。
- 8 张图片统一放入 `li-lu/images/`。
- 图片文件名增加文章标识前缀，避免三个源目录中重复的 `image.png` 相互覆盖。
- Markdown 中的相对图片地址仍使用 `images/<name>.png`；加载器统一改写为站点绝对路径 `/li-lu/images/<name>.png`。

这样可以复用当前语料加载和图片路由约定，同时让静态构建不依赖外部文件夹。

## 数据模型与加载

`OriginalSource.type` 从现有的 `"shareholder" | "speech"` 扩展为：

```ts
"shareholder" | "speech" | "li-lu"
```

原文目录配置集中描述目录、类型和显示名称：

| 目录 | 类型 | 显示名称 |
| --- | --- | --- |
| `shareholders/` | `shareholder` | 股东会与股东信 |
| `speech/` | `speech` | 演讲与访谈 |
| `li-lu/` | `li-lu` | 李录演讲和访谈 |

`loadOriginalSources()` 继续返回统一的 `OriginalSource[]`。标题优先取 Markdown 第一处一级标题，缺少一级标题时退回文件名；年份继续从文件路径或正文中推断。新资料沿用现有 slug、摘要、标题目录和 Markdown 渲染逻辑。

类型名称由一个共享映射提供，侧栏、原文索引、单篇页和 SEO 不再各自使用二选一三元表达式，避免第三种类型被误标为“演讲与访谈”。

## 页面与导航

### 左侧导航

“原文”下面依次显示：

1. 股东会与股东信
2. 演讲与访谈
3. 李录演讲和访谈

第三组显示 14 篇，按年份升序、同年按中文标题排序。进入任一李录资料页时，该组自动展开并标记当前文章。

### 原文索引与首页

`/sources/` 新增 `#li-lu` 分区，显示名称、篇数、摘要和年份。首页原文入口新增“李录演讲和访谈”卡片，链接到该锚点。

原文索引页的描述扩展为同时覆盖查理·芒格和李录资料，但不修改整个站点的主品牌。

### 单篇原文页

李录资料继续使用 `/sources/<slug>/`，不增加第二套路由。页头和信息栏显示“李录演讲和访谈”。“同类原文”限定为同一 `type` 且同一年，避免李录资料与同年份的芒格资料混排。

现有解释文章没有声明李录资料为来源，因此初始“解读引用”数量可以为 0；这不是错误。

### 图片

现有图片动态路由允许 `li-lu` 作为合法目录，并从 `li-lu/images/` 生成静态图片路径。继续保留目录白名单和路径穿越防护。

## 数据流

```text
外部李录目录（一次性来源）
  -> 复制并规范路径
仓库 li-lu/*.md + li-lu/images/*.png
  -> loadOriginalSources()
OriginalSource(type = "li-lu")
  -> 侧栏 / 首页 / 原文索引 / 单篇原文页
  -> sitemap / llms-full / 结构化数据
```

部署阶段只读取仓库内 `li-lu/`，不再访问外部来源目录。

## 异常与边界处理

- 无一级标题的文章使用文件名作为标题。
- 无明确年份的文章显示“未标明”，并按现有排序规则处理。
- 源文件中的空链接（例如指向缺失 PDF 的 `[]()`）保持原样，不伪造资源。
- 图片只接受白名单目录内的 `.png` 文件；非法目录、包含 `/` 或 `..` 的图片参数返回 404。
- 复制过程中不覆盖同名图片，而是通过文章前缀生成唯一文件名。
