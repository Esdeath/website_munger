# 思维格栅网格首页设计

**日期：** 2026-07-13
**状态：** 已确认，等待实现计划评审

## 目标

将 `/thinking-grids/` 从 Markdown 长文索引改为思维模型的可视化入口：一个页面包含 12 个主题模块，每个模块包含多个可点击的模型格子，并进入既有的独立模型页面。

## 页面范围

- 首页只显示页面标题和 12 个模块；不显示原始索引中的导语、外部说明链接或“使用顺序”。
- 模块顺序、名称、问题、用途和模型归属完全来自项目内独立快照 `thinking-grids/思维格栅.md`。
- 每个模型格子链接到既有的 `/thinking-grids/<slug>/` 页面；不新增或改动模型详情页。
- 左侧“思维格栅”一级导航和快照的独立维护策略保持不变。

## 布局与交互

```
页面标题：思维格栅

┌──────────────── 模块 1 ────────────────┐  ┌──────────────── 模块 2 ────────────────┐
│ 01  思维操作系统 · 24 个模型             │  │ 02  数学与概率 · 16 个模型                │
│ 我该如何思考？                            │  │ 数量、概率、分布和期望是什么？             │
│ [五何原则] [二阶效应] [双轨分析] ...      │  │ [不对称性] [乘法系统] [决策树] ...        │
└────────────────────────────────────────┘  └────────────────────────────────────────┘
```

- 桌面端为两列模块卡片；较窄的屏幕退为单列，避免压缩模型名称。
- 每张卡片展示两位层级编号、模块名称、模型总数、“先问”提示与“用途”说明。
- 模型格子在卡片内自适应换行。悬停和键盘焦点使用现有橙色主题的边框/底色反馈；格子名称保持可读并可直接点击。
- 只使用 CSS 布局，不添加前端脚本、筛选器或状态管理。

## 数据与错误处理

1. `src/lib/thinking-grid.ts` 在既有快照加载后解析索引：按二级标题切出 12 个模块，提取紧随其后的“先问”“用途”和 Markdown 表格中的本地模型链接。
2. 解析结果引用已加载的 `snapshot.models`，使用现有 slug 与 URL 生成规则，确保首页与模型静态路由一致。
3. 若未解析到恰好 12 个模块、模块缺少模型链接，或索引中的本地模型链接找不到对应快照文件，加载器在构建期报错，避免静默遗漏模型。

## 验证

- 为解析器新增测试：断言得到 12 个模块、模型合计为 178 个，以及代表模型的名称和 URL。
- 首页模板测试或构建产物检查：确认不再输出原始导语和“使用顺序”，并包含 12 个模块及 178 个本地模型链接。
- 执行 `npm run check`，再检查 `dist/thinking-grids/index.html` 的模块数量与模型链接数量。

## 非目标

- 不改变 `thinking-grids/` 的独立快照性质，也不读取外部项目。
- 不改动模型正文、详情页、左侧导航或全站主题。
- 不将模块分类写死在页面模板或独立配置中；索引文件仍是唯一分类来源。
