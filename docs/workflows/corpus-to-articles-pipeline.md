# 从语料到文章的通用流水线

这份文档只讲可迁移的方法论:如何把一组固定资料库变成可验证、可维护、对读者有用的主题文章。
本仓库的逐步操作手册见 [`generate-articles-best-practices.md`](generate-articles-best-practices.md)。

## 目标

把原始资料生成文章时,同时满足三件事:

1. **正确第一**:所有引用和事实都能回到原始语料。
2. **读者有用**:文章不是资料摘抄,而是帮读者理解一个可复用判断。
3. **可低成本复用**:下一批文章或下一个资料库能沿用同一套状态、模板和校验方式。

## 为什么要先建流水线

直接写文章最容易出现四类失败:

- 引用像原话,实际不是逐字原文。
- 选题听起来重要,但语料覆盖不够,凑不满引用和来源门槛。
- 文章通过机器校验,但解释太薄,对读者没有真实帮助。
- 流程、状态、模板、索引混在一个文件里,下一次无法复用。

所以顺序必须是:先固定语料和校验合同,再写文章。

## 通用组件

| 组件 | 任务 | 本仓库对应 |
|---|---|---|
| 语料目录 | 提供唯一事实来源 | `shareholders/`、`speech/` |
| 校验器 | 机器检查硬门槛 | `tools/check_article.py` |
| 文章模板 | 统一单篇结构 | `docs/reference/article-template.md` |
| 状态清单 | 记录选题、完成状态和坑 | `docs/state/article-backlog.md` |
| 成品索引 | 给读者浏览文章库 | `docs/reference/article-index.md` |
| 执行手册 | 给下次操作者照着做 | `docs/workflows/generate-articles-best-practices.md` |

每个组件只做一件事。不要把待办写进模板,不要把流程写进索引,不要把文章正文写进状态清单。

## 标准流水线

1. **固定语料**
   明确哪些目录是唯一来源。没有进入语料目录的材料,不能作为引用和事实依据。

2. **建立校验合同**
   写一个脚本检查硬门槛:引用逐字存在、引用数达标、来源数达标、frontmatter 完整、必备小节存在。

3. **建立选题池**
   按读者需求分类,而不是按资料出现顺序分类。一个好选题应该能回答“读者为什么现在需要这篇文章”。

4. **做可行性预检**
   用关键词、同义词和案例名搜索语料。先确认覆盖和来源数,再决定是否写。

5. **窄读取证**
   只读命中行附近上下文,抽取候选引用和事实。优先跨年份、跨场合、跨来源取样。

6. **形成文章角度**
   先写一句文章要解决的问题,再选引用。不要先堆引用再硬凑主题。

7. **按模板成文**
   正文负责解释和连接,blockquote 负责展示逐字证据。编者的话和原文引用必须分清。

8. **单篇校验**
   写完一篇就跑校验器。失败时回到原始语料修正,不要凭记忆改引文。

9. **人工复核**
   机器能证明“逐字存在”,不能证明“用得正确”。人工检查说话人、年份、上下文、数字和语义外推。

10. **同步状态和索引**
    用校验器输出更新引用数和完成状态。索引只写成品介绍,状态清单只写进度和选词注意事项。

11. **全量复验**
    批次结束前全量跑校验,再做空白字符和工作区检查。

## 质量顺序

1. **正确**:逐字引用、事实准确、出处清楚。
2. **有用**:能解释一个判断,有案例、边界和误读提醒。
3. **省时间**:先预检低覆盖题,少做无效写作。
4. **省 token**:搜索优先,窄读优先,只把必要上下文带入写作。

不能为了省时间牺牲正确性;不能为了省 token 省掉必要的上下文核查。

## 迁移到其他资料库

在新资料库复用时,只替换组件,不改顺序:

| 要替换的部件 | 本仓库 | 新资料库需要准备 |
|---|---|---|
| 语料目录 | `shareholders/`、`speech/` | 固定的 Markdown 资料目录 |
| 成品目录 | `articles/` | 新文章输出目录 |
| 校验器 | `tools/check_article.py` | 能逐字核验新语料的脚本 |
| 模板 | `docs/reference/article-template.md` | 适合新读者和主题的文章模板 |
| 状态清单 | `docs/state/article-backlog.md` | 新选题池和进度 |
| 索引 | `docs/reference/article-index.md` | 新成品目录 |

迁移时先试产 1 篇。只有当这 1 篇能通过机器校验、人工复核和读者价值检查后,再批量生成。

## 完成定义

一套文章生产流程可以复用,必须满足:

- 新人只读执行手册就能生成下一篇。
- 每条引用都能被脚本回查到语料。
- 文章质量不只依赖脚本,还包含人工语义核查。
- 状态、模板、索引、流程文件没有职责混杂。
- 批次结束后能用一组命令复验。
